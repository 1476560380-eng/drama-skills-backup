# 短剧创作系统使用说明书

> 适用：Hermes duanju profile · 11 个 short-drama 技能（官方全套 + storyboard 升级版）
> 项目根目录：`~/duanju/` · 当前活跃项目：《末世选择》

---

## 一、一句话理解

这套系统把短剧/漫剧创作拆成 **11 个各管一段的技能**，像剧组一样分工。
你对我说人话，我自动调对应技能；**不用记命令**，说清楚想干什么就行。

## 二、系统全貌（创作流水线）

```
小说/点子 ──→ ①novel-analyze ──→ ②develop ──→ ③write ──→ ④assets ──→ ⑤image-prompts
                 (拆原著)        (开发立契约)   (写剧本)   (拆视觉资产)   (图片提示词)
                                                                          │
成片 ←── ⑨edit ←── ⑧produce ←── ⑦video-prompts ←── ⑥storyboard ←────────┘
        (剪辑)      (付费生产)      (视频提示词)        (分镜+关键帧)
        
        ⑩review 全程可插（审任何阶段，只报问题不改文件）
        ⑪short-drama 总调度（建项目/看进度/跨阶段路由/机械核对）
```

**核心铁律：**
- 创作类技能只写文档，**不生成媒体**
- `produce` 是唯一花钱的环节，**每次都必须你明确点头**，预览/预算说明/既往确认都不算
- 五份核心文档是唯一真相：`剧本.md`、`视觉设定.md`、`分镜.md`、`图片提示词.md`、`视频提示词.md`

## 五、分镜技能（升级版）特别说明

你部署的 storyboard 是定制升级版，比官方多五样，**默认开启**：

| 增强项 | 给你带来什么 |
|---|---|
| 镜头技术捕捉 | 每镜三拍式笔触（起幅→运镜意图→落幅交接），分镜可直接指导生成/拍摄 |
| **运镜（独立字段）** | 每镜一行「行为＋理由」，下游视频提示词直接抄这一行 |
| 配音指令 | 有对白的镜逐句标 `角色｜音色｜状态｜语速`，攒起来直接喂 TTS |
| SEG 段落 | 每 3–5 镜归段写情绪+色调，防逐镜生成画风漂移 |
| 镜长 0.5s 精度 | 对白镜先按发声时间估，节奏更准 |

说「这集分镜精简模式，不要增强规格」可整组关闭。

## 六、画幅：先定 16:9 横屏还是 9:16 竖屏

**画幅是项目级决定，写在 `short-drama.json` 的 `format.aspect_ratio`，技能不会替你默认竖屏。**

| 画幅 | 适合什么 | 构图规则 |
|---|---|---|
| **16:9 横屏** | 环境叙事、群像、多人对峙、动作场面、系列剧 | 全谱系景别都能用；远景/全景是强项，横向铺开的信息一次装得下；要主动分配画面左右两侧的信息，情绪落点仍靠近景/特写单独给 |
| 9:16 竖屏 | 手机端连续短剧、单人对峙、快速消费 | 以中景/近景/特写为主；用纵深分层（前景/中景/后景）交代空间；远景全景少用 |

画幅一旦定了，**关键帧正文、图片提示词正文、视频提示词里的画幅句必须全项目一致**（如
`Horizontal 16:9 cinematic 2D anime drama still...`）。中途改画幅 = 所有已生成的图重画。

初始化项目时如果没说画幅，我会问一次，不再默认竖屏。

## 七、质量闸门（本系统最重要的改动）
官方检查器缺一份文档就整体退出，等于逼你「五份全写完才敢检查」。所以补了局部校验器：

```bash
python3 ~/.hermes/profiles/duanju/skills/short-drama/scripts/episode_lint.py 剧集/EP001
```

它只查**当前存在的**文档，缺的跳过不算错。查什么：视觉设定条目格式、镜头标题中文名、
运镜字段、图片提示词项书名号与原名一致、冻结关键帧引用块、视觉依据可解析、SEG 时长算术、
头部合计与逐镜相加是否一致。

**三条铁律：**
1. **每写完一份就跑一次**，不要等五份齐
2. **从模板起写**，不要从空白页起：`short-drama/templates/视觉设定模板.md`、`分镜模板.md`
3. **工序顺序固定**：定目标模型+集长 → 出定调图/身份板 → 分镜 → 视频提示词 → 完整核对 → 审查

## 八、题材热度怎么查

说「查一下当下短剧什么题材热」，跑 `short-drama-novel-analyze/scripts/heat_probe.py`，
聚合 5 个免费源（百度热搜/头条热榜/B站热搜/豆瓣在播剧/番茄小说榜），按 16 条赛道统计命中数。
判读：**番茄榜单（供给端）+ 豆瓣在播（需求端）同时命中**才算题材真热；只有新闻热榜命中只是社会话题。
云合、DataEye、红果等平台数据需你提供截图，脚本抓不到，也不会编造。

## 十一、约定与边界

- **你只管创作决定**：画风、集长、目标模型、接受/拒绝节奏档案——系统只在你确认后落档
- **文档是唯一真相**：对话里的草稿不算数，以 `剧集/<EP>/` 里的文件为准；你说「剧本已确认」指的是文件，不是聊天记录
- **改动可追溯**：拆镜/并镜保留未受影响的镜头 ID；要刷新哪些下游文件会说清楚，但不自动改你没点名的文件
- **审查不改稿**：review 只出问题清单和修订要求，动笔改永远由对应负责技能执行
