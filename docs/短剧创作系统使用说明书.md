## 一、一分钟看懂

这套系统把一部短剧拆成 **11 个各管一段的技能**，像剧组分工。你说人话，我自动调对应技能。

```
你给小说
   ↓
①拆原著 ─→ ②开发立契约 ─→ ③写剧本 ─→ ④拆视觉资产 ─→ ⑤图片提示词
                                                              ↓
成片 ←─ ⑨剪辑 ←─ ⑧生产 ←─ ⑦视频提示词 ←─ ⑥分镜+冻结关键帧 ←┘
                    （花钱，必须你点头）

⑩审查全程可插 · ⑪总调度管进度和路由
```

**三条底层规则：**

| 规则 | 含义 |
|---|---|
| 创作类只写文档 | ①–⑦ 一步都不生成媒体，只产出 Markdown 文档 |
| `produce` 是唯一花钱的环节 | 每次都必须你明确确认；预览、预算说明、上次确认过都不算 |
| 五份文档是唯一真相 | `剧集/<EP>/` 里的 `剧本.md`、`视觉设定.md`、`图片提示词.md`、`分镜.md`、`视频提示词.md`；对话里的草稿不算数 |

## 二、系统组成

### 11 个技能

| 技能 | 干什么 | 产出 |
|---|---|---|
| `short-drama` | 总调度：建项目、看进度、跨阶段路由 | `short-drama.json`、`开工清单.md` |
| `short-drama-novel-analyze` | 拆原著、判改编价值、切分集候选 | `source-analysis/` 下整套分析 |
| `short-drama-develop` | 改编契约、故事引擎、分集地图 | `creative-brief.md`、`story-engine.md`、`adaptation-map.jsonl` |
| `short-drama-write` | 写/改单集剧本 | `剧本.md` |
| `short-drama-assets` | 拆人物/造型/地点/道具/连续性 | `视觉设定.md` |
| `short-drama-image-prompts` | 写出图提示词（不生成图） | `图片提示词.md` |
| `short-drama-storyboard` | 分镜 + 冻结关键帧（你的升级版） | `分镜.md` |
| `short-drama-video-prompts` | 视频生成提示词 + 配乐意图 | `视频提示词.md` |
| `short-drama-produce` | 跑图/跑视频/TTS/配乐（付费） | `制作成果/` |
| `short-drama-edit` | 套剪、字幕、响度、导出 | `交付/` |
| `short-drama-review` | 审任何阶段，只报问题不改文件 | `审查/` |

### 3 个自建工具（官方没有的）

| 工具 | 作用 | 为什么需要 |
|---|---|---|
| `episode_lint.py` | **局部校验**：缺文档也能跑 | 官方检查器缺一份文档就整体退出，等于逼你五份全写完才敢检查 |
| `start_project.py` | 一键开工：四项必答 → 建项目 → 写开工清单 | 避免「先做起来再补配置」导致返工 |
| `heat_probe.py` | 题材热度探针：5 个免费源 → 16 条赛道命中数 | 改编选题要热度证据，但不能编造数据 |

### 2 个模板（照抄即合规）

- `short-drama/templates/视觉设定模板.md`
- `short-drama/templates/分镜模板.md`

模板里已经把检查器逐条核对的东西写死了，**从模板起写，不要从空白页起**——这是避免格式返工最省事的办法。

## 三、开工：四项必答

你一说「我要做新项目」，我会**主动问**这四项（不用你提醒）：

| 顺序 | 我要问的 | 例子 |
|---|---|---|
| 1 | 新项目叫什么？ | 《深夜外卖》 |
| 2 | 每集多少秒？共几集？ | 每集 90 秒，第一季 10 集 |
| 3 | 用什么视频模型？ | Seedance 2.0 / 可灵 / MiniMax H3 / 即梦 |
| 4 | 什么题材？ | 复仇爽剧 / 甜宠 / 悬疑规则 / 逆袭 |

**不用问的**：画幅默认 **16:9 横屏**、关键帧正文英文（你要别的直接说）。

四项齐了，我跑一键开工：

```bash
python3 ~/.hermes/profiles/duanju/skills/short-drama/scripts/start_project.py \
  --dir ~/duanju/深夜外卖 --title "深夜外卖" \
  --seconds 90 --episodes 10 --model seedance-2.0 --genre "复仇爽剧" \
  --novel "输入/原著.txt"
```

它做的事：建项目目录 → 写 `short-drama.json`（画幅 16:9、90 秒、10 集）→ 写 `项目开发/开工清单.md`（四项落档）→ 打印下一步该跑哪个技能。**缺参数直接拒绝执行**，不会留半成品。

## 四、阶段一：小说改编导入（拆原著）

你的项目默认从这里开始。

### 你提供什么

- 原著文件（`输入/原著.txt` 或 `.md`，长篇直接给全文）
- 或只有书名/链接，我先把文本放进 `输入/`

### 我做哪几步（S0–S5）

| 步 | 动作 | 产出 | 是否停靠 |
|---|---|---|---|
| S0 | 建稳定章节索引（唯一切片真相） | `source-analysis/_index.json` | 否 |
| S1 | **改编价值快评**（抽样 12 章，首尾必取） | `triage.md` | **停这里问你**：值不值得全量拆 |
| S2 | 逐章功能提取（每批 5–8 章并发） | `chapters/ch-N-extract.md` | 否 |
| S3–S4 | 剧情单元聚合、节奏与人物归并 | `story-units.md`、`rhythm-and-emotion.md`、`characters.md` | 否 |
| S5 | **改编价值与分集候选** | `adaptation-value.md`、`episode-candidates.jsonl` | 交接给开发 |

命令（我执行，你看结果）：

```bash
python3 .../short-drama-novel-analyze/scripts/novel_index.py index 输入/原著.txt
python3 .../novel_index.py sample 项目开发/source-analysis/_index.json --count 12
python3 .../novel_index.py coverage 项目开发/source-analysis/_index.json 项目开发/source-analysis/chapters
```

### 改编价值怎么判

判据是**改编密度**，不是文笔好坏：

| 类别 | 含义 | 短剧里的价值 |
|---|---|---|
| `screen_ready` | 能直接拍成画面的动作、对白、冲突 | 高 |
| `prose_only` | 内心戏、叙述性诡计、长铺垫——画面上无法兑现 | 低，要换载体 |
| 混合 | 需要改编手法转换 | 看转换成本 |

快评要回答六件事：故事框架、三类判定比例、开篇替换点、制作负担量级、最大三处改编风险、分集候选量级。

### 题材赛道对照（必写一行）

快评另加一行：原著属于哪条短剧赛道、是否在当下热门序列。

取数跑热度探针（抓不到平台数据时写「未提供热度数据」，**绝不编造榜单**）：

```bash
python3 .../short-drama-novel-analyze/scripts/heat_probe.py --quiet
```

判读：**番茄榜单（供给端）+ 豆瓣在播剧（需求端）同时命中**才算题材真热；只有新闻热榜命中只是社会话题。

### 交接条件

S5 完成 → 向你说清：拆了多少章、跳过哪些、切了多少候选集、最大三处改编风险、快评里被推翻的判断。你点头后进开发。

## 五、阶段二：开发与改编契约

### 做什么

把分集候选变成可拍的方案：改编方案、戏剧方向、创作简报、故事引擎、分集地图。

产出：`项目开发/creative-brief.md`、`story-engine.md`、`adaptation-map.jsonl`、`episode-map.jsonl`

### 改编的铁律

- **保留**原著核心人物的立场、核心关系、主线
- 原著没有的新增内容，一律登记为 `add` 并列进简报，让你看见改了什么
- 上一阶段的分析是输入，不是结论——你已接受的改动优先

### 同时定三件事（定了才往下走）

| 决定 | 影响 |
|---|---|
| 制作形态（写实/2D漫剧/3D/水墨…） | 决定画风统一句、关键帧词表 |
| 节奏档案（平均镜长、近景占比、首钩秒数…） | 你接受后，分镜按它核对数值；不接受就不核对 |
| 目标视频模型 | 决定视频提示词的方言与参考图张数上限 |

## 六、阶段三：写剧本

### 做什么

按分集地图写单集可拍摄剧本，产出 `剧集/EP001/剧本.md`。

### 格式要求

- 场景用 ID：`## EP001-SC001 外 · 废墟城市街道 · 黄昏`（分镜的「来源」字段会回链到这些 ID）
- 对白用「角色：台词」，角色名与视觉设定一致
- 一个场景写清：地点、时间、在场人物、动作、对白、画面文字

### 可用脚本

```bash
python3 .../short-drama-write/scripts/duration_estimate.py 剧本.md --index <项目索引>
```

按项目声明的语速估算时长，避免「写完发现超时」或「不够 90 秒」。

### 停靠点

剧本写完**必须你确认采用**。之后分镜读的是文件，不是你我在对话里改过的草稿。

## 七、阶段四：视觉资产（拆角色/场景/道具）

### 做什么

从剧本里拆出需要保持一致的东西：人物与造型、地点、道具与状态、跨场连续性锁。产出 `视觉设定.md`。

### 强制格式（检查器只认这个）

```markdown
## 人物 · 林羽

- **定位**：主角
- **识别锚点**：26–27 岁东亚男性，短发微乱，深灰蓝旧夹克，右袖口暗红血渍
- **本集状态**：健康 → 鼻血 → 集末虚弱
- 画面代称：Lin Yu

## 地点 · 废墟城市街道

- **ID**：LOC-001
- **地理**：倒塌高架桥压住半条街，中间是废墟超市
- 画面代称：ruined street
```

**三条硬规矩：**

1. 条目必须是 `## 类别 · 名称`（类别只能是 人物/造型/地点/道具）
2. `画面代称` 行**不能加粗**（写成 `- 画面代称：Lin Yu`）
3. 名称要和分镜里引用的名字逐字一致

写错的后果很重：写成 `## 人物` + `### 林羽` 会让分镜里所有「视觉依据」集体失效（一次报几十条错）。

直接复制 `templates/视觉设定模板.md` 起写。

## 八、阶段五：图片提示词

### 做什么

为每个角色/地点/道具写一条**可直接复制去出图**的提示词，产出 `图片提示词.md`。这一步不生成图。

### 格式

```markdown
## IMG-LINYU-ID · 林羽身份板

- 用途：锁定身份、体态和本集造型。
- 参考：无

### 可复制提示词
> Character identity sheet, horizontal 16:9 cinematic 2D anime drama style, ...
```

### 关键点

- 标题格式 `## IMG-XXX · 中文名`——分镜引用时**中文名必须逐字等于这个标题**
- 正文放 `### 可复制提示词` 的 `>` 引用块里，一条就是一次生成
- 画幅句与项目一致（16:9 → `horizontal 16:9`）
- 画风统一句全项目同一句，写实就写写实，不要混入「插画」「漫剧」这类会把图拉偏的词

### 出图顺序（建议）

先出 **1 张定调图**（主角+环境的定场镜）→ 你接受 → 再批量出身份板 → 再出起始帧。定调图不接受就批量，等于全废。

## 九、阶段六：分镜与冻结关键帧

### 做什么

把剧本和视觉设定变成可拍的镜头表，产出 `分镜.md`。这是你的升级版技能（当前 **2.9.0**），比官方多 11 样（默认启用）：

| 增强 | 内容 | 版本 |
|---|---|---|
| 镜头技术捕捉 | 每镜三拍：起幅（从哪开始）→ 运镜意图（为什么动/不动）→ 落幅交接（停在哪格、下一镜从哪接） | 2.0 |
| **运镜（独立字段）** | 一行「行为＋理由」，下游视频提示词直接抄 | 2.0 |
| 配音指令 | 有对白的镜逐句 `角色｜音色｜状态｜语速（约Ns）`，直接喂 TTS；**「约Ns」是真实语速的唯一依据** | 2.0 |
| SEG 段落 | 每 3–5 镜归段，写总时长+情绪基调+色调，防逐镜生成画风漂移 | 2.0 |
| 镜长 0.5s 精度 | 对白镜先按发声时间估，再排动作与停顿 | 2.0 |
| **镜头时间码** | 镜头标题带全集时间轴区间（如 `· 巷口夜行（0.0–3.0s）`），逐镜累加、末尾核对算术和，拼片免算 | 2.6 |
| **节尾承接块** | 每集末尾写「交接下集」：末镜状态／轴线锁定／未完成动作／剧情停点／下集待接／建议接镜 | 2.6 |
| **生成包分组** | 按 SEG 边界切包 + 模型原生时长窗口 4–15s + 超窗二分 + 长对白镜独占 + 包间续接链；改片半径从「重赌单镜」降到「重出一包」 | 2.7 |
| **对白发声窗口预核** | 同轨生成多镜时先核台词念得完，防吞字 | 2.7 |
| **节奏与情绪设计** | 先画情绪曲线再分镜；SEG 可选「节奏定位」；声音当节奏工具（静音蓄力／J-cut／L-cut）；三种蒙太奇压缩配方 | 2.8 |
| **镜头语言＋段级调色** | SEG 段可写「镜头基准」（焦段/景深）与「光线锚点」；关键帧画风句拆成「全局质感锁 + 按段翻译的调色词」；微表情按「动作后定格」写法 | 2.9 |
| **画面位置与轴线锁** | SEG 段头开轴线账；每镜关键帧正文写 `on screen-left / on screen-right / facing screen-…`；走位镜标 `not part of the dialogue axis`。左右锁直接长在提示词里，不另出检查文件 | 2.10 |
| **强制项 fail-closed** | 轴线锁＋亮度口径默认强制（0 覆盖也报错）；`强制项` 行声明子集；老集必须显式写 `- 规格：legacy` 才豁免 | 2.14 |
| **曝光校准** | 每条关键帧必须含一句曝光句（夜景保暗部 / 日景保高光 / 火光不烧核心 / 剪影声明）；暗部不糊死、高光不烧白、有人物写清面部受光来源；段头可加「曝光基准」 | 2.11 |
| **亮度四层** | ①调色词拆「色相+明度」（禁单用 moody/muted 代表亮度）②每条写 key + fill 两个光源，逆光必须有补光，人脸对背景 ≤1:4 ③负面词 `underexposed, crushed blacks, murky shadows` ④曝光句 | 2.12 |

### 每镜必填字段

```markdown
## SHOT-EP001-001 · 题面入画

- **职责**：本镜唯一要完成的事
- **来源**：EP001-SC001「剧本里的短引文」
- **时长**：4.0s
- **景别/机位**：低角度仰视全景
- **运镜**：缓慢上摇（起幅人群剪影 → 落幅题面）；理由：信息量大，固定会压小文字
- **镜头技术捕捉**：起幅 → 运镜意图 → 落幅交接
- **起点 → 唯一动作 → 终点**：起点 → 动作 → 终点
- **声音**：环境声/对白
- **配音指令**：角色｜音色｜状态｜语速（约3s）：逐字台词
- **视觉依据**：《视觉设定.md》·人物「林羽」（控制：本镜承担得起的范围）
- **图片提示词项**：IMG-LINYU-ID《林羽身份板》（控制：身份）
- **输入参考图**：无（待补参考图：本镜起始帧）

### 冻结关键帧提示词

> 英文正文，只写镜头起点这一刻看得见的东西
```

### 九条硬规矩

1. 标题 `## SHOT-<EP>-<序号> · 中文名`，不能只有编号
2. 图片提示词项用 `IMG-XXX《标题原名》（控制：…）`——书名号，名称逐字等于图片提示词标题
3. 冻结关键帧 / 收尾关键帧正文必须是 `> ` 引用块
4. 每镜必须有 `运镜` 字段
5. 视觉依据里的名字必须能在视觉设定里找到；不入画的写 `；画外：人物「名字」`（不带括号说明）
6. 「未拍场次」要么不写，要么写 `<场景ID>（理由：…）`
7. **画面位置**：有人物出场的镜，关键帧正文必须写左右（`on screen-left` / `on screen-right` / `facing screen-…`）；走位穿场写 `not part of the dialogue axis`；纯物件/空镜可免
8. **轴线账**：每个 SEG 段头写一行 `轴线：甲 ↔ 乙｜机位：…｜甲 画面左 / 乙 画面右`；写不出轴线账的场次不得拆分镜
9. **亮度四层**：①调色词拆「色相+明度」（`teal-and-amber grade, mid-key exposure, shadows lifted`；禁单用 moody/muted/dark）②写 `key:` 与 `fill:` 两个光源，逆光/夜景必须有补光，人脸对背景 ≤1:4 ③负面词 `underexposed, crushed blacks, murky shadows` ④一句曝光校准

### 写完立刻校验

```bash
python3 .../short-drama/scripts/episode_lint.py 剧集/EP001 --only 分镜
```

查的就是上面六条 + SEG 时长算术 + 头部合计是否等于逐镜相加。**有错当场改，别等下一阶段。**

## 十、阶段七：视频提示词

### 做什么

把分镜和冻结关键帧写成可直接复制的视频生成提示词，产出 `视频提示词.md`。一个镜头一条 `MOTION-...`。

### 格式

```markdown
## MOTION-EP001-001 · 题面入画

- 分镜：SHOT-EP001-001
- 时长：4s
- 生成方式：图生视频
- 输入参考图：<必须与分镜那一行逐字一致>
- 静态视觉锚点：<执行动作所需的可见起点>
- 起始帧：SHOT-EP001-001 的冻结关键帧
- 状态链：起点 → 动作 → 终点
- 终点：<可验证的结束状态>

### 可复制提示词
> 该模型的方言正文……
```

### 生成包任务单（2.7 起，默认按包输出）

分镜里的「生成包总表」直接决定这一步怎么输出：**每包一张任务单**，而不是一镜一条。每张任务单包含：

| 项 | 内容 |
|---|---|
| 出场人物与声线锁定 | `@人物图[音色]`，把人物图和 TTS 音色一起锁死 |
| 场景与风格句 | 匹配场景 + 风格句（负面指令写在前面） |
| 逐镜条目 | 时间码 + 运镜 + 首帧 `@` 绑定 + 位置承接 |

Seedance 2.0 方言另有 2.7.1 补充：**多镜容器正文顶部要声明总镜数**，作为切点判定锚（该手法尚未实测，用前先小样验证）。

### 三种参考图路线（这一步的枢纽）

| 路线 | 含义 | 前置 |
|---|---|---|
| **图生视频 + REF** | 项目里已有真实图片 | 你出图并入项目，我绑 `REF-...` |
| **图生视频 + PLAN** | 你在自己的工具里出图，生成时手动挂载 | 我写 `PLAN-...` 槽位，声明挂哪几张 |
| **文生视频** | 不用任何参考图 | 必须**你明确说**「这集不用参考图」 |

**注意**：`待补参考图` 会硬性阻断最终视频提示词——这是技能的设计，不是 bug。卡在这里只有上面三条路。

### 方言

不同模型格式完全不同（Seedance 用 `<声音>`、`【字幕】` 标记；MiniMax 用 `overall_soundscape`；wan 要单写配乐层）。**先定模型再写提示词**，否则要重写。

默认禁字幕、默认单镜素材不自带配乐（配乐走剪辑的时间线）。

## 十九、常见问题

**Q：我可以跳过拆原著，直接写剧本吗？**
可以。已有剧本就直接进 `$short-drama-write` 或资产流程，开发文件不强制补。但改编项目跳过拆书，容易丢原著的主线和人物立场。

**Q：为什么非要先定视频模型？**
不同模型的提示词格式完全不同，参考图数量上限也不同（比如 Seedance 2.0 最多 9 张）。模型不定就写提示词，等于赌。

**Q：每集多少秒谁说了算？**
你。但一旦定了就写进档案，分镜的镜长和节奏档案会按它核对。没定就别排版镜长，写了必返工。

**Q：图一定要我自己出吗？**
三条路：① 你出图放进项目我绑 `REF` ② 你出图不放进项目，我写 `PLAN` ③ 明确改走文生视频（一致性最差）。

**Q：检查器报了上百条错，是不是系统坏了？**
通常是一个格式根因导致的连锁（比如视觉设定写法不对 → 几十条视觉依据失效）。先跑 `episode_lint.py` 看第一类错，往往是改一处好一片。

**Q：能不能直接生成视频？**
能，但要你先确认模型、配好 adapter、并且明确点头付费。这三样缺一不可。

**Q：《末世选择》是什么？**
是格式样品，不是你的正式项目。作用是对照格式（已转 16:9、已过校验），不用推进它。

## 十九点五、项目卡（每个项目一张，一屏看完）

每个项目有一张 `项目开发/项目卡.md`，把口径汇总成一屏：画幅、集长、模型、画风统一句（逐集列）、强制项、人物与画面代称、配音音色、各集进度。

**为什么要它**：项目事实原本散在 `short-drama.json`、开工清单、各集分镜里，三处会互相矛盾（实测《阈限空间》曾有 3 条不一致）。卡把矛盾摊在「⚠️ 待裁决」区，而不是替你挑一个。

| 操作 | 命令 |
|---|---|
| 生成/刷新 | `python3 scripts/project_card.py <项目目录>` |
| 只查是否过期 | `python3 scripts/project_card.py <项目目录> --check` |

**三条铁律**：
1. 卡是索引不是真相——真相仍在 json、开工清单和各集文档
2. 卡由脚本生成，**手改无效**（下次生成会覆盖）
3. 卡里「待裁决」有内容时，按你的决定改源文件，再刷新卡

`episode_lint.py` 会提示「项目卡已过期」——源文件比卡新的时候。
