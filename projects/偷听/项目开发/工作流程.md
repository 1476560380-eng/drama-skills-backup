# 《偷听》单集生产工作流程 v1.1.0

> 2026-10-29 定稿，同日 v1.1.0 增补阶段 3 完整卡规范（独立成篇：`项目开发/图片提示词卡规范.md`）。本流程以 EP001 全程实操跑通为基准，适用于后续每一集。
> 手工流，不依赖生成器脚本（用户 2026-10-29 确认："就你这个思路来"）。

## 一、阶段 0：建档

四项必须问清（EP001 教训：选择表单未送达就自作主张用了默认值，被用户指出。表单发出去要确认送达，没送达就改在聊天里直接问）：

1. 题材定位（一句话＋复合标签＋受众）
2. 画幅（本项目固定 16:9 横屏）
3. 单集时长（本项目：依故事内容定，60–120s 区间，每集定稿后写入该集文档）
4. 目标视频模型（本项目：Seedance 2.0，原生 4–15s 窗口）

题材定位原文照录入开工清单，agent 不改写、不概括。

## 二、阶段 1：剧本收录

**铁律：不改故事内容。** 用户的原文一字不动，agent 只做三件格式事：

1. 加集标题＋场景头（SC001、SC002…，按空间转换切）
2. 「动作＋冒号＋台词」拆成独立动作段＋`角色：台词`；说话动词留在动作段
3. 可加三类标签（可撤）：`[画面文字]`（石碑刻字等）、`[SFX]`（音效）、`[连续性]`（跨场状态）

验收：脚本逐字比对，净字数一致、差异只有标点断句。原文另存 `输入/original-epXXX.md` 永不改。

发现剧本自身矛盾（如 EP001 小药"已在旁边说话"vs"从手里蹦出来化形"）：**照原文拍，矛盾报给用户，不擅自补戏。**

## 三、阶段 2：视觉设定

每集产三类条目：人物 / 地点 / 道具。每条含：

- 识别锚点（长相/材质/尺寸，如"左眼下小痣"）
- 本集状态变化（哪一镜起变了什么）
- 英文画面代称（下游提示词引用）
- 跨镜不变锁（全集不许漂的项）

另加两节：**Q版切点**（剧本标（Q版）的镜号才切，Q 版只用于喜剧拍子）、**下集交接状态**（EP002 开场时每个条目长什么样）。

参考图纪律：用户给的参考图只是方向，不照抄、不挂进生成；人物场景按剧本描述重建。画风参考管色彩光影质感、人物参考管长相体格、环境参考管空间陈设，互不越界。

## 四、阶段 3：图片提示词（锤爆卡式）

细则真源独立成篇：**`项目开发/图片提示词卡规范.md` v1.0**（下表只留骨架，写卡时照那篇走）。

- **选卡型**（一卡一资产，不许同卡画两个）：T-CHA 人物 / T-CHA 状态变体 / T-GRP 群像 / T-LOC 场景 / T-PRP 道具 / T-UI 界面
- **通用硬规则**：编号 `IMG-EPxxx-C/L/PXX`＋卡名跨集逐字不变（回填分镜"图片提示词项"）；纯白底 #FFFFFF＋极浅冷灰细线；4K 出图（720p 验收不了四视图，脸只有约 35px）；渲染尾逐字 `3D Chinese animation style，semi-realistic，high-end CG，studio lighting，soft film grain`
- **人物卡五区**：左（姓名＋资料＋主肖像）/ 中（**完整四视图**，全卡主体）/ 右（三格表情＋头部细节＋主色板）/ 底（动态＋局部＋线稿＋比例尺）/ 右下（AI 演员声明逐字）。四视图一致性四句必写；表情写肌肉动作不写空词；比例尺用部位锚线不写厘米数
- **场景卡**：纯四等分四视角、固定地理 100%、不加细节条不写文字条；光线写"四格共享同一套光源＋允许视角明暗差＋禁止拉平亮度"，不许写"四格亮度一致"
- **道具卡**：多视角＋微距＋状态对照；资产自带文字（石碑"洛洛药庐"）逐字写明允许可读
- **状态变体**（C02 药汁态/C03 Q版）：【基准锁定】＋【本状态差异逐条对照】；Q 版变体保留识别锚点、只用于剧本标（Q版）的镜
- **中文卡式**（本项目 prompt_language=zh-CN），分段标题按卡规范第十节逐字沿用，不改段落名
- **验收四项**：四视图同一张脸 / 两侧面相反＋背面在 / 三格表情可分 / HEX 与实际一致

**出图顺序**：先 3 张定调卡（L01 场景＋C01 主角＋核心配角）→ 试 3 镜验证 → 过了再批量。不要一上来出全量。场景四宫格不直接当关键帧参考，挂分镜用单视角干净图。

## 五、阶段 4：锚图登记

用户出图发回后：

1. 存 `输入/参考图/`，逐张解析写 `解析.md`
2. 登记进 `登记表.md`：**每类只 1 张锚**（人物锚=C01 洛洛，场景锚=L01），其余算辅助图照样能挂
3. **图上实际样子回写设定**：用户出的图和文字设定有差异时，以图为准改视觉设定和分镜描述（EP001 改了 6 处：金花枝簪、细垂辫、白短靴、伞盖大于身体、棕褐身体、瀑布等）
4. 分镜里所有"输入参考图：待补"刷新成真实挂图；人物镜必须同时挂场景图（EP001 踩坑：004 没挂 L01，整座药庐峰消失）
5. 挂图顺序：主人物第 1 格（权重最大），双人镜洛洛恒在第 1 格

尺寸提醒：720p 当参考够、当验收卡不够（脸 40px 验不了小痣），关键帧出图按 4K。

## 六、阶段 5：分镜

按剧情拍子切段（SEG-01…），逐镜字段：

```
## SHOT-XXX（段内序号）
- 职责 / 来源（对应剧本场景）
- 时长 / 景别 / 机位
- 运镜＋理由（镜头按剧情表现力选，不套模板）
- 起幅 → 意图 → 落幅
- 起点 → 动作 → 终点（动作链用剧本原话，不发明动作）
- 声音 / 配音指令（角色｜音色｜状态｜语速）
- 视觉依据（画内人物＋地点＋道具，决定挂哪些锚图）
- 图片提示词项 / 待补参考图
- ShotDeck 逐词中英对照
- 时间码
- 冻结关键帧（可直接复制的出图正文：画面位置句＋亮度四层＋曝光句＋负面词）
```

**开场规则（用户 2026-10-29 定）**：第一镜就是人，不给纯空镜开场；空镜改插入镜。

**时长规则**：空镜/动作镜 1.5–2.5s；台词镜按字数给（喜剧极限 6 字/秒，压不动就如实报"这是台词自己的长度"）。

**剧本动作三不**：不加戏（小药没写动作就不动）、不减戏、不改变形/动作过程的写法。

## 七、阶段 6：生成包切分

- Seedance 2.0 原生 4–15s：每个包总时长落在窗口内，**中间包和末尾包都要 ≥4s**（EP001 踩坑：只检查了末包，中间包 3.0s 漏网）
- 不跨 SEG 段切包
- 切完核对：包数、每包时长、包内镜数、全集总时长三方对账（分镜求和 = 包求和 = 段求和）

## 八、阶段 7：多镜容器（手工）

每包一份，头部＋逐镜，版式：

```
Horizontal 16:9, 3D Chinese animation style, semi-realistic, high-end CG,
studio lighting, soft film grain。禁止出现字幕，禁止出现背景音乐，禁止出现水印

【本包结构】N 个硬切镜，总 Xs。切点：t1/t2/…。每镜时长严格按下述数字，不得合并、不得延长。
【本包场景】…
【本段色彩意图】…（块外，不进可复制块）
【出场人物】…
【开场要求】（如第一镜是人，写死）

镜头N / SHOT-XXX（起-止秒）
【镜头参数】Shot on …（源分镜原句）
【运镜】…
【画面】起点 → 动作 → 终点（剧本原话）
【位置承接】人名 画面左/右；面朝…；空镜写"无人物"
【音效】…
【台词】角色｜音色｜状态｜语速：内容（无则写"无"）
```

沿用锤爆七项规则：①风格块=首镜质感锁原文＋三项禁止 ②镜头参数=源分镜 Shot on 句 ③时间锚 ④位置承接按人名归属中文句 ⑤容器禁元话语（理由/职责留分镜给剪辑）⑥画内人物=视觉依据∪英文首帧点名 ⑦中英人名双轨。

## 九、阶段 8：验证闭环（方案 C，用户 2026-10-29 确认）

**不做全量 45 张，也不零图直出**，走混合：

1. 只出定调卡 3 张（L01/C01/C04）
2. 三镜验证：单人近景（验脸，同句提示词出 2 次必须同一张脸）＋双人同框（验两卡兼容）＋全景（验场景卡）
3. 试点包 01 一条多镜视频，验四条：**开场是不是人 / 脸漂不漂 / 切点听不听话 / 场景动作对不对**
4. 过了 → 后续每包只出"首镜＋包内最露脸 1–2 镜"，全量图可砍约半
5. 不过 → 降级逐镜出首帧，明说 Seedance 撑不住直出

验收记录落盘（哪条过哪条不过、根因、修改），不模棱两可。

## 十、阶段 9：规则沉淀（踩坑即写入 文件规则.md）

EP001 已沉淀的坑：

| 坑 | 规则 |
|---|---|
| 脚本 split+join 丢换行，45 个标题粘行（连踩两次） | 改分镜必须 `'\n'.join` 拼回＋核对行首 `## SHOT` 标题数＋重跑 episode_lint（改完只跑参考图核对不算校验） |
| 人物镜没挂场景图，整座山消失 | 人物镜"视觉依据"必须含地点，必须同挂场景锚图 |
| 提示词正文与锚图设定不一致（旧描述残留） | 锚图登记后全量刷分镜里的外观描述 |
| 双人镜挂图顺序错 | 主人物恒第 1 格 |
| 表单未送达就自作主张 | 表单确认送达，否则聊天里直接问 |

## 十一、通用纪律

- **改前备份**（.bak-日期），删文件先问或留"已弃用"标注（EP001 误删提示词_v1 教训）
- **版本号铁律**：每次改进给版本号，改完同步 VERSION/CHANGELOG/说明书
- **交付即给卡片**：文件改完同一条回复里给 MEDIA 链接
- 术语用大白话＋表格解释；结论附可复现命令/证据，明说"已改"还是"诊断"
- 用户说"先讨论不要改"是硬约束，点头才动文件
