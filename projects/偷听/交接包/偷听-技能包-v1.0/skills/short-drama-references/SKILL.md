# 短剧参考图生命周期

参考图进项目先分类，一类图只干一类活。**不是给你一张图就全部模仿**——画风参考只管色彩光影质感，人物形象参考只管长相体格，环境参考只管空间陈设，越界的部分一律写进「不得控制」。

## 何时用本技能

- 创作者发来参考图（画风、人物、环境、动作、道具）
- 要给某张图定「它能控制什么、不能控制什么」
- 要换风格锚、加锚、退役某张图
- 项目里已有参考图但不确定分镜/图片提示词绑得对不对

**不管**：提示词正文（`$short-drama-image-prompts`）、镜头与关键帧（`$short-drama-storyboard`）、出图（`$short-drama-produce`）、视觉方向比较（`$short-drama` 的 Look Development）。

## 四步闸门

```
图进项目 → ①分类登记 → ②解析报告 → ③锚图裁决 → ④绑定与验证
```

### ① 分类登记（`输入/参考图/登记表.md`）

**「这些是参考图」不等于「登记成锚图」。** 创作者发图时默认只给方向（色彩、材质、气质、时代调性），不是身份锚；先问一句这批图是「出图时要挂的」还是「只作方向」。只作方向的不进登记表、不绑 `REF-...`、不占锚位，人物与场景仍按剧本描述重建（见 `$short-drama-assets` 的「剧本事实优先于参考图」）；确认要挂图出图时才走下面四步。

**五类，一张图一个主类**：`画风` / `人物形象` / `环境` / `动作` / `道具`。

- 分类由质检方（我）**初判**并在解析报告里写明「判定为 X 类，理由是 Y」；**创作者确认后才登记**，不许自判自绑——把人物图误判成画风图的后果是脸被污染，不可逆。
- 一图多槽：一张图可以同时是好画风和好构图，但**先在登记表「次类」列声明**（如 `画风` + 次类 `环境`），绑定时才允许开第二个槽位；未声明的跨类用途直接报错，每个槽位用途仍须单一。
- 外部图（创作者在自己工具里挂着用、文件不进项目）**不许写 `REF-...`**：`REF-` 的语义是「文件此刻在项目里」。外部图走 `PLAN-...` 槽位，或在解析报告里标明「外部图，不进项目」。
- 文件名用英文/数字/连字符，避免中文与空格。
- **表情九宫格/表情板主类判 `动作`（表情范式），次类可声明 `画风`**：它给的是「怎么演」，不是「长什么样」；板上带整版中文说明文字的，必须在「不得控制」里写死不出文字，出图后逐张检查有没有把说明字画进画面。
- **带字幕或平台水印的剧集截屏**：主类按画面主体判（多数是 `环境`），但含人物或叙事景物时按下面的裁块规则——只能裁成材质块后进画风槽，整张不许挂。

模板：[templates/登记表.md](templates/登记表.md)

### ② 解析报告（`输入/参考图/解析.md`）

每张图一节，固定六项：分类复核、色板采样（近似 HEX）、光位与硬度、质感归类、与现有视觉设定的冲突点、建议绑定范围与挂图顺序。

- **报告中文、大白话、表格对照**；英文词必须跟中文解释。报告是给创作者看的，不是给自己看的。
- **观察边界**：实际看过图才报「实际所见」；看不到图时写「未验证」，不得声称水印、文字、裁切或身份已通过。
- 色板是采样近似值，注明「以人眼裁决为准」。

格式与验收判据：[references/解析报告与验收.md](references/解析报告与验收.md)

### ③ 锚图裁决

- 每类**最多 1 张锚图**（`锚` 列填 `✅`），其余是辅助图；同类多锚视为错误。
- **两个主要人物是常态，不是多锚**：锚位按「类别」计，但人物图按「资产」用。两个及以上主要人物时，
  让一个主角占该类锚位填 `✅`，其余各人在表里各占一行、`锚` 列留空，备注写「辅助图（类锚位由 X 占）」——
  辅助图照样能被 `REF-...` 绑定、照样能锁脸，只是不叫锚。**不要为了过检查把人物图改判成画风类**，
  那是拿错类图凑数，后果是脸被污染。
- 缺类的项目不阻塞：用文字质感锁顶着，报告里明写「本类无参考」。**不许拿错类图凑数**（比如用环境图当画风锚）。
- **锚变更不追认历史**：换锚只影响变更之后的条目，历史集数已生成的图不回写、不重生成。换锚时用 `ref_check.py --change-anchor` 算传播账。
- EP 间默认沿用同一套锚；某集要破格，在分镜 SEG 段头声明，不许默默换。

### ④ 绑定与验证

- 绑定前必须跑 `scripts/ref_check.py <项目根>`：分类↔用途必须对齐，跨类即报错。
- **A/B 只做两类**：画风锚与人物锚必须验证（污染后果最重）；环境/道具/动作可合并一次验证或跳过。
  - 画风锚 → 用**场景定调图**验（中性灰身份板验不出剧情光下的画风）
  - 人物锚 → 用**身份板**验
- 绑画风参考时，同镜正文要有负面词（`不复制参考中的人物与场景内容` / `do not copy people or set from the reference`），因为多数出图工具对参考图是「照着画」。
- **实景剧照不能直接挂进生成**（2026-10-25 实测）：负面词擦不掉参考图里已有的像素——挂一张电影剧照，工具会把剧中人物、服装、背包和外景天空整块搬进设定卡，三格视图里出来的是剧照里那个演员的脸。含人物或叙事景物的照片参考，必须先裁成「无人、无叙事景物」的材质块（只保留材质、光比、颗粒），存成新文件并在登记表备注「裁切材质块（裁自 XX）」，才允许进提示词。人物卡与道具卡不挂照片参考，画风改由文字质感锁＋HEX 色板承担；地点卡只挂材质块。
- 裁块要真的看过：每块裁完逐张确认无人脸、无人物肢体、无叙事物件（车、尸体、文字），常见失败是边缘带进半个肩膀或一只靴子。
- 创作者在自己工具里出图时，报告必须输出**挂图顺序**（哪张放第几格），否则他不知道怎么挂。
- **图回来之后，以图为准反向回写文字。** 创作者按卡片出图后，实际图与卡片文字几乎总有偏差（发饰材质、鞋型、伞盖比例、身体配色、场景里多出的瀑布与栏杆）——这些偏差不是瑕疵，是新的基准。逐张对完解析报告的「冲突点」后，一次改三处：
  ①《视觉设定.md》的识别锚点与连续性锁（锁面是英文，改完后续关键帧会原样拄进去）；
  ②《图片提示词.md》对应卡的描述与色板（不改，下次重出会照旧错）；
  ③分镜里所有关键帧正文的同一批措辞（改完 `grep 旧词` 确认清零）。
  漏掉任一处，下游就会出现「卡片说素银簪、锚图是金花簪、关键帧还在写素银簪」三方打架。
- **缺口要一次列清、按优先级排**：哪几张卡已出、哪几张还缺（人物状态卡、其余场景、全部道具），按「定调图 + 人物身份图 → 其余场景 → 道具 → 状态变体/Q 版」排序。Q 版这类形态卡未出时，明确写「不挂正片人物图，只作脸型对照」，否则模型会把正片的脸直接画成 Q 版。

## 分类 → 用途映射（硬校验依据）

| 分类 | 唯一允许的 `用途` | 说明 |
|---|---|---|
| 画风 | `风格` | 只管色彩层级、材质、阴影边缘、景深、密度 |
| 人物形象 | `身份`、`造型状态` | 唯一允许控制长相的类别 |
| 环境 | `地理`、`构图` | 不管色调（色调归画风） |
| 道具 | `身份`、`造型状态` | 形制跨镜不变用身份，开合破损用造型状态 |
| 动作 | `构图`、`效果` | 图片阶段只能锁定格姿态，**主要服务视频提示词阶段** |

用途封闭词表与边界细则见 `$short-drama` 的《参考角色》；本表只做分类到用途的收窄，不新增用途词。

## 与 Look Development 的边界

| | 本技能（仓库管理员） | Look Development（品控） |
|---|---|---|
| 管什么 | 图从哪来、怎么登记、属于哪类、谁是锚 | 视觉方向的比较与接受 |
| 产物 | 登记表 + 解析报告 | 代表帧方向比较 |
| 关系 | 解析报告喂给 Look Dev 使用 | 不反向改登记与分类 |

## 登记表的机器口径（ref_check.py 怎么读这张表）

检查器只认极窄的格式，一处格式错会刷出几十条假错误，按下面四条写一次就过：

1. **「文件」列只写项目相对路径**，不要带中文名、书名号或备注。写成 `输入/参考图/ref-x.png《中文名》`
   会被整串当文件名，报「文件不存在」，并连带把分镜里每一个 `REF-...` 都报成「未在登记表登记」。
   中文名、用途、控制范围都放「备注」列。
2. **「不进生成」的图不能出现在同一张表的表格行里**——它们会被当成登记行，报「主类不合法」。
   改成表格外的一段列表（`- 路径 — 说明`），并明写「只作方向参考，不进任何生成」。
3. **文件名与本项目锚图的命名要能对上**：`ref-<卡号>-<资产>.png` 这种带卡号的形式最好用，
   绑定时的 `REF-...` 与分镜里的路径逐字一致就能对上。
4. **锚图分辨率有下限**：项目按 4K 出资产卡时，1280×720 的四视图脸只有约 40px，小痣、缝线级锚点
   **验收不了**。这种尺寸只能当挂图参考，要在解析报告里直接标明「作参考可用、作验收卡需重出 4K」——
   不要因为文件名合格就默认它能验收。

## 脚本

```bash
python3 scripts/ref_check.py <项目根>                 # 全量核对，退出码 1 = 有问题
python3 scripts/ref_check.py <项目根> --json          # 机器可读
python3 scripts/ref_check.py <项目根> --change-anchor # 换锚传播账
```

查什么：登记表字段与文件存在性、每类锚数上限、`REF-` 槽位是否已登记、分类与用途是否对齐、同图跨类违规、外部图误写 `REF-`、解析报告必备小节、画风参考负面词、失效引用。

## 完成

图已分类登记、解析报告六项齐全、锚图每类至多 1 张、绑定校验通过（`ref_check.py` 退出码 0）、分类对应的 A/B 验收已过，即完成。提示词正文、分镜与出图不自动开始。
