# 灵魂文件说明 · 锤爆世界

> 生成时间：2026-10-25。本文回答一个问题：**这个短剧系统里，"项目的灵魂"存在哪个文件、怎么表达、想改规则走哪条路。**
> 说明：短剧系统里没有一个文件叫"灵魂文件"，这个职责由下面三层文件共同承担。

---

## 一、三层结构总览

| 层 | 文件 | 位置 | 角色 | 一句话理解 |
|---|---|---|---|---|
| 机器层 | `short-drama.json` | 项目根目录 | 项目身份证：唯一 ID、画幅、时长、语言等硬参数 | 机器读的"户口本" |
| 灵魂层 | `文件规则.md` | `项目开发/` | **真正的灵魂文件**：所有创作文件必须遵守的规则的唯一载体 | 你说过的话都在这 |
| 索引层 | `项目卡.md` + `开工清单.md` | `项目开发/` | 卡片是索引不是真相，规则正文从灵魂层整段抄进去 | 抄出来的摘要 |

## 二、各层现状（锤爆世界）

| `production_profile` | 制作方式（目标视频模型等） |

这三块等创作过程中逐步定，定一个填一个。

### 2. 灵魂层 `文件规则.md`（核心）

文件开头自己声明了三件事：

1. **唯一载体**——每个创作文件必须遵守的规则只在这一处改；
2. **来源**——规则来自创作者历次明确交代的写法要求，不是技能默认值；
3. **优先级**——与技能冲突时，以本文件为准，冲突列进项目卡「待裁决」。

它锁死了五类文件的写法（要点摘录）：

| 文件 | 灵魂层锁住的关键规矩 |
|---|---|
| 剧本.md | 对白冒号前必须带括号提示；时间按剧情拍子排，不按集长砍戏 |
| 视觉设定.md | 条目格式 `## 类别 · 名称`；先识别锚点再本集状态；连续性锁只锁跨镜不变事实 |
| 图片提示词.md | 中文卡式 / 英文身份板二选一不混写；色板必给 HEX；氛围词无效、镜头语言有效 |
| 分镜.md | 轴线锁 fail-closed；镜头逐镜选逐镜写理由，严禁套模板；静帧化；亮度四层；ShotDeck 参考行逐词中英对照 |
| 视频提示词.md | 按目标模型方言写；模型未定不写；缓推=slow dolly in 禁 zoom |

### 3. 索引层 `项目卡.md` / `开工清单.md`

- 项目卡由脚本 `short-drama/scripts/project_card.py` 生成，**手改无效**（下次生成会覆盖），规则正文的源头是灵魂层；
- 源文件互相矛盾时列「待裁决」，不许自行挑一个往下做。

## 三、规则怎么流动

```
你提出要求（聊天里说）
        ↓
写进 文件规则.md（唯一改规则的入口）
        ↓
脚本重新生成 项目卡.md（自动把规则整段抄进去）
        ↓
约束所有后续剧集文件：剧本 → 视觉设定 → 图片提示词 → 分镜 → 视频提示词
```

## 四、想让新要求变成"系统级灵魂"的操作路径

1. **改一个地方**：`项目开发/文件规则.md`，加一条或改一条；
2. **重新生成项目卡**：跑 `project_card.py`（或让 agent 执行），新规则自动进卡；
3. **对已有文件**：规则只约束之后的写作；旧文件要不要按新规则改写，由你单独决定（"技能升级≠改旧本子"）。
